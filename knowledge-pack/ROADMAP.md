- Deep-dive consolidation (UX): the real, sourced data is combined into one **Verified identity, licence and financials** card (identity/profile strip + Ofgem licence + live GLEIF verify + Companies House financials). The company summary and profile cards are merged (score bars removed), the score breakdown sits under the qualification assessment (half width), and the **Origination decision** is a full-width, emphasised card. Fields already shown in the verified card, and evidence bullets that restate it, are hidden for the featured counterparty to remove duplication.
- Counterparties table tidy: **Data quality** moved before Country; the scenario selector is emphasised with a "Showing" label, primary styling and a contextual hint (scored vs universe); the shortlist CTA in the table is reduced to icon + count.
- "How it works" (`/faq`) expanded: added a high-level **data pipeline** (8 steps), an **originator workflow** strip and a **configuration workflow** strip, and refreshed the FAQs for the real data slices (GLEIF live, Ofgem + Companies House snapshots) and the configurable source registry.
- **Prototype access gate**: a simple username/password sign-in gates the app (`src/lib/auth.tsx` + `LoginScreen`, gated in `__root.tsx`); the signed-in role is reflected in the app and a sign-out control sits in the sidebar. Session persists under `deal-scout.auth.v1`. Client-side only, not real security (see D25); SSO/OIDC is the production item.
- Nav and shell tidy: **Library** moved first under Configuration; the scope subtitle removed from the sidebar; the Home "Micro-CRM" card renamed "CRM".
- **Criteria library redesigned (UX overhaul):** the library moved from an all-expanded wall of editors to a master-detail layout: a persistent left index (type-ahead search over criteria and data fields; filter chips for All / Blocking / Needs setup / Duplicate field; themed sections Financial strength / Market access / Volume / Infrastructure; a weight-distribution bar) plus a single right-hand editor for the selected criterion. Rule and direction collapsed into one plain-English rule select (Higher is better / Lower is better / Pass-fail at least / at most / In a range); thresholds are now typed number fields with units plus an interactive score curve (hover to read value to score) instead of sliders; one blocking control on the criterion; importance shown as a live percentage of total weight (criterion and sub); status is first-class (Needs setup / Blocking / Inactive / Duplicate field) with a needs-setup banner; data field shows unit, source and real coverage (share of the universe with a value); single-sub criteria render inline (no wrapper); delete moved into a row overflow menu with a confirm, plus duplicate-as-template. A new criterion-level default weight (`LibraryCriterion.weight`) makes importance-as-% real at the library level (scenario overrides still win). Parked for a later phase (agreed with UX): the live before/after counterparty-sample feedback panel, and change history / undo / drag-reorder / archive. See DECISIONS D29.
- **Audit layer, Phase 1 (compliance traceability):** a new `src/lib/audit.ts` assembles a self-contained, re-computable evidence record per counterparty + scenario: header (counterparty + LEI + jurisdiction, scenario, user, timestamps, ruleset + source-registry SHA-256 hashes), a live-source verification block (GLEIF, regulator licence, financials), the full source -> value -> rule -> sub-score -> weight chain, the fit / band / blocked result, the system recommendation + basis, and the human decision. A SHA-256 content hash makes tampering detectable. The deep dive shows an "Audit trail" card (only for the live-source counterparties) with two downloads: canonical JSON (record of account) and a printable HTML dossier (print to PDF). No new dependencies. Immutability caveat stated in-app: the prototype log is browser-side, so tamper-proof append-only storage is Phase 2. See DECISIONS D28.
- **Validation batch wired (3 real DACH counterparties, plus Yü Energy for GB):** Trianel GmbH (DE, LEI 529900A42A65AFJG6O09), VERBUND Energy4Business GmbH (AT, LEI 529900RTYBY8TPW9U991), BKW Energie AG (CH, LEI HP4455X23HMJWUDSIO96), each with a live GLEIF verify, a regulator licence snapshot (BNetzA/CEREMP, E-Control, ElCom), and financials (Bundesanzeiger / VERBUND AG group / BKW annual report). Region-aware sourcing attributes each field to the correct register per jurisdiction; the verified-data licence block is now regulator-generic (not Ofgem-only); the store injects all real-data counterparties so they always load. Balance-sheet figures tightened against the 2024 filed accounts (Trianel group equity ~EUR 875m; VERBUND AG group equity ~EUR 11.06bn; BKW equity ~CHF 5.8bn, net debt ~CHF 1.25bn); net-debt lines remain the softest input and are flagged approximate. Trading Market Access is now wired to real signals for three of its six criteria (exchange membership, traded-volume proxy, net-assets proxy); the soft three (product overlap, existing DMA, regulatory permissions gap) stay as graceful no-data placeholders. The trading houses can be scored on either Demand or Trading Market Access via the deep-dive scenario switch. See the validation note.
- **Criteria library now covers Michael's full scenario/criteria set** (from `Origination Scenarios_Criteria.xlsx`). The wired Demand Market Access criteria stay; every other scenario's criteria are generated from `scenarios[].spec` (deduped, tagged per scenario via `LibraryCriterion.scenarios`, inverse and optional respected). `resolveScenario` filters the library to the selected scenario. Criteria without wired data show as "no data" and are excluded from the fit (they do not drag it down). Existing sub-criteria preserved; thresholds/weights are starter defaults and the new criteria's data fields are placeholders pending wiring on the Library and Sources screens.
- Deep dive is **scenario-switchable**: a scenario selector on the deep dive re-runs the score breakdown, fit and Blocked flag for the chosen scenario (defaults to the globally selected one). Note the AI suggestion/basis text is per-counterparty seed data, so it does not change with the scenario. Source `coverage` on `/sources` is now edited via region chips (GLOBAL / EU / each region), not free text.
- **Region-aware source resolution (Phase A of multi-region):** sources now declare `coverage` (region codes) and the field-to-source map is per region (`FieldSourceMap`), resolved by the counterparty's `jurisdiction` (exact region, then EU fallback, then default). GLEIF stays global. Seeded GB + DACH sources (Companies House, Ofgem, Bundesanzeiger, Firmenbuch, Zefix, BNetzA, E-Control, ElCom, EEX/ICE, Elexon, ENTSOG). The `/sources` screen gains a region selector and editable per-source coverage. Prompted by Michael's originator list being all DACH: the authoritative register varies by jurisdiction. Rules engine and scoring unchanged.
